# 04 — หลักบัญชีและภาษี (Accounting Engine Rules)

เอกสารนี้คือ "สมอง" ของระบบ: ทุกเอกสารธุรกรรมต้องสร้างสมุดรายวัน (journal) อัตโนมัติตามกฎด้านล่าง

> **สถานะการยืนยันกับ PEAK จริง (9 พ.ย. 2569, ดู 09)**: แถวที่มี ✅ = เห็น journal จริงจาก PEAK แล้ว · ⚠️ = PEAK ทำต่างจากที่เขียนไว้เดิม แก้แล้ว · (VAT) = ยืนยันแล้วในรอบ 2 (09 §4) — ภาษีขาย 215101/215102 และภาษีซื้อ 115402→115401 ผ่าน JVTX
รหัสบัญชีอ้างอิงผังบัญชีมาตรฐาน PEAK (ดู 05) — **Observed** จากระบบต้นแบบ; สมการ Dr/Cr เป็นมาตรฐานบัญชีไทย (TFRS for NPAEs) ที่ PEAK ใช้ — **Inferred** จาก account names + referenceTransactionType ที่ journal อ้างกลับไปยังเอกสาร

## 0. หลักการคงที่ (Invariants) — ระบบต้องบังคับใน DB/Service layer

1. ทุก journal: `Σ debit = Σ credit` (เราเช็คที่ DB CHECK + service)
2. แต่ละ journal entry เป็น debit หรือ credit อย่างใดอย่างหนึ่ง ไม่มีค่าติดลบ
3. เอกสาร `Approve` เท่านั้นที่สร้าง journal; `Draft` ไม่กระทบบัญชี
4. เอกสารที่ Approve แล้ว **แก้ไม่ได้** → ต้อง Void แล้วออกใหม่; PEAK void = ตั้ง `isVoid=1` บน journal เดิมแล้ว**ไม่นับใน TB/GL** (ไม่สร้างใบกลับรายการ) ✅ — ระบบเราใช้วิธีเดียวกัน (soft-void) เพื่อให้ตัวเลขตรง PEAK
5. Void ไม่ได้ถ้ามีเอกสารอื่นอ้างอิงอยู่ (CN→INV, RT→INV, EXP→PO, DR ที่ถูก draw down) → ต้อง void ปลายทางก่อน
6. Void ไม่ได้ถ้าเอกสารถูกส่ง e-Tax Invoice แล้ว เว้นแต่ยืนยัน `isVoidETaxInvoice=1` (compliance action)
7. งวดบัญชีที่ล็อก (locked period): ห้ามสร้าง/void journal ที่ `issuedDate`, `taxInvoiceDate`, `journalDate` ตกในงวดนั้น
8. ภาษีซื้อ: `periodDate` ต้องอยู่ในเดือน `taxInvoiceDate` ถึง +6 เดือน (สิทธิ์ขอคืนภาษีซื้อย้อนหลัง 6 เดือนตาม ป.รัษฎากร ม.82/3)
9. เลขที่ใบกำกับภาษีซื้อซ้ำต่อ vendor เดียวกัน → ปฏิเสธตอน Approve
10. WHT: `paymentAmount = netAmount − withHoldingTaxAmount`; ต้องส่ง WHT ทั้งระดับ line และระดับ payment พร้อมกัน
11. `discountTotal` ใช้ได้เฉพาะเมื่อทุก line มี vatType เดียวกัน
12. ทศนิยม: เก็บ 2 ตำแหน่ง (THB) ปัดครึ่งขึ้น (ROUND_HALF_UP) ที่ระดับเอกสาร ไม่ใช่ระดับ line — VAT คำนวณจาก preTax รวม ✅ (PEAK: 3×33.33=99.99 → VAT 7.00)
13. เลขที่เอกสารที่เป็น**ใบกำกับภาษี**ใช้ชุดเลขแยก (PEAK: IVT-/RT-/DRT- vs IV-/RE-/DR-) และห้ามนำเลขที่ void แล้วกลับมาใช้ (PEAK reuse ได้ — เราไม่ทำตาม)

## 1. การคำนวณยอดเอกสาร

```
line_amount      = quantity × price − line_discount
subtotal         = Σ line_amount (ที่ไม่ใช่ isDescription)
after_discount   = subtotal − discountTotal

taxStatus = 0 ExcludeTax : preTax = after_discount
                           vat    = Σ(line ที่ vatType=3) × 0.07
                           net    = preTax + vat
taxStatus = 1 IncludeTax : net    = after_discount
                           vat    = Σ(line vatType=3) × 7/107
                           preTax = net − vat
taxStatus = 2 NonTax     : preTax = net = after_discount, vat = 0 (บังคับทุก line vatType=1)

wht      = Σ line.withHoldingTaxAmount
payable  = net − wht
```

vatType ต่อ line: 1 None (ยกเว้น/ไม่จด VAT), 2 ZeroPercent (ส่งออก, 0%), 3 SevenPercent

## 3. ภาษีมูลค่าเพิ่ม (VAT) — ภ.พ.30

### Tax point (จุดความรับผิด)
| กิจกรรม | จุดเกิด VAT | บัญชี |
|---|---|---|
| ขายสินค้า | ส่งมอบ / โอนกรรมสิทธิ์ / รับเงิน / ออกใบกำกับ — อันใดก่อน | 215101 ทันทีตอน Approve INV ที่ isTaxInvoice=1 |
| ให้บริการ | รับชำระเงิน / ออกใบกำกับ — อันใดก่อน | INV → 215102 รอเรียกเก็บ; Receipt → โอนไป 215101 |
| มัดจำ | รับเงินมัดจำ | 215101 ทันที |
| ซื้อ มีใบกำกับ ✅ | journalDate ที่ลงทะเบียนใบกำกับ | เอกสารลง 115402 ก่อน แล้ว **JVTX** (สมุดรายวันภาษี) Dr 115401 / Cr 115402 ต่อใบกำกับ |
| ซื้อ ยังไม่ได้ใบกำกับ ✅ | — | 115402 ค้างไว้ → ออก JVTX เมื่อลงทะเบียนใบกำกับภายหลัง |

### รายงานภาษีขาย (Output VAT report)
แหล่งข้อมูล: เอกสาร 102/103/105/121 ที่ `isTaxInvoice=1`, status Approve, ไม่ void, เดือนตาม tax point
คอลัมน์ตามกฎหมาย: ลำดับ, วัน/เดือน/ปี, เลขที่ใบกำกับภาษี, ชื่อผู้ซื้อ, เลขผู้เสียภาษี, สำนักงานใหญ่/สาขา, มูลค่าสินค้า/บริการ, จำนวน VAT

### รายงานภาษีซื้อ (Input VAT report)
แหล่งข้อมูล: `received_tax_invoice` ที่ `period_date` = เดือนที่ยื่น (= journal JVTX ใน PEAK); คอลัมน์เหมือนภาษีขายแต่เป็นผู้ขาย
**ระบบเรา**: ให้ posting engine ทำตามต้นแบบ — เอกสารซื้อ Dr 115402 เสมอ, การลงทะเบียนใบกำกับสร้าง journal ประเภท `tax` (JVTX) Dr 115401 / Cr 115402 แยก 1 ใบต่อใบกำกับ → รายงานภาษีซื้อ = Σ JVTX ของเดือน period_date
ใบกำกับที่ `periodDate` ล่าช้า (ภายใน 6 เดือน) จะปรากฏในเดือนที่เลือกยื่น ไม่ใช่เดือนในใบกำกับ

### ภ.พ.30 สรุป
```
ยอดขาย (ไม่รวม VAT)          = Σ preTax ภาษีขาย
ยอดขายที่เสีย 0%             = Σ line vatType=2
ยอดขายยกเว้น                 = Σ line vatType=1 (ถ้าจด VAT)
ภาษีขาย                      = Σ vat (215101 เคลื่อนไหว Cr)
ภาษีซื้อ                     = Σ vat (115401 เคลื่อนไหว Dr) ที่ขอคืนได้
ภาษีสุทธิ                     = ภาษีขาย − ภาษีซื้อ (+ ยอดยกมาเครดิตเดือนก่อน)
ยื่น + ชำระภายในวันที่ 15 ของเดือนถัดไป (23 ถ้ายื่นออนไลน์)
```

### ภาษีซื้อต้องห้าม (ขอคืนไม่ได้) → 540201/540202
ค่ารับรอง, รถยนต์นั่งไม่เกิน 10 ที่นั่ง, ใบกำกับไม่สมบูรณ์, ไม่เกี่ยวกับกิจการ — ระบบควรให้ติ๊ก "ไม่ขอคืน" ต่อ line → ลง 540201 แทน 115401

### กิจการไม่จด VAT
`isTaxInvoice=0`, ทุก line `vatType=1`, ค่า VAT ของซื้อรวมเข้าต้นทุน/ค่าใช้จ่าย (ไม่แยก 115401)

## 4. ภาษีหัก ณ ที่จ่าย (WHT)

### ฝั่งเราถูกหัก (ลูกค้าหักเรา) → 115403 ภาษีถูกหัก ณ ที่จ่าย (สินทรัพย์)
เกิดกับ Receipt / Invoice+payment / Billing Note payment / DR; ต้องเก็บหนังสือรับรอง 50 ทวิ ที่ได้รับ เพื่อเครดิตภาษีสิ้นปี (ภ.ง.ด.50)

### ฝั่งเราหักผู้อื่น (เราจ่ายเงิน) → 215203 ภ.ง.ด.3 ค้างจ่าย / 215204 ภ.ง.ด.53 ค้างจ่าย (หนี้สิน)

> **พฤติกรรม PEAK ที่เห็นจริง**: API ไม่มี field เลือกแบบ ภ.ง.ด. PEAK เลือกจาก contact.type — นิติบุคคล → 215204 (ภ.ง.ด.53) ✅ ; บุคคลธรรมดา → **215201 (ภ.ง.ด.1)** ซึ่งผิดสำหรับค่าจ้าง/ค่าบริการบุคคลภายนอก (ต้องเป็น ภ.ง.ด.3) → ระบบเราต้องมี `wht_form` ต่อรายการ และ default: บุคคล + บัญชีเงินเดือน 5301xx → PND1, บุคคล + อื่น → PND3, นิติบุคคล → PND53, ผู้รับต่างประเทศ → PND54
เกิดกับ Expense+payment / IR payment / DP / BNX payment
ระบบต้องออก **หนังสือรับรอง 50 ทวิ** ให้ผู้รับเงิน และยื่น:
| แบบ | ผู้รับเงิน | กำหนดยื่น |
|---|---|---|
| ภ.ง.ด.3 | บุคคลธรรมดา (contact type 5, 6, 8) | วันที่ 7 เดือนถัดไป (15 ออนไลน์) |
| ภ.ง.ด.53 | นิติบุคคล (type 1, 2, 3, 9, 10, 11) | วันที่ 7 เดือนถัดไป (15 ออนไลน์) |
| ภ.ง.ด.1 | เงินเดือนพนักงาน | วันที่ 7 เดือนถัดไป |

อัตรามาตรฐาน (ให้ระบบเสนอ แต่ user override ได้): ค่าบริการ/จ้างทำของ 3%, ค่าเช่า 5%, ค่าโฆษณา 2%, ค่าขนส่ง 1%, ค่าวิชาชีพอิสระ 3%, เงินปันผล 10%, ดอกเบี้ย 1% (นิติบุคคล) / 15% (บุคคล), รางวัล/ส่วนลด 3%, ขั้นต่ำ 1,000 บาทต่อครั้ง (ยกเว้นสัญญาต่อเนื่อง)

ข้อมูลที่ต้องเก็บต่อรายการ (ตาราง `wht_certificate`): ประเภทเงินได้ (40(1)-40(8)), อัตรา, ฐาน, ภาษี, วันที่จ่าย, เลขที่หนังสือรับรอง, ผู้หัก/ผู้ถูกหัก + เลขผู้เสียภาษี + สาขา, เงื่อนไข (หัก ณ ที่จ่าย / ออกให้ตลอดไป / ออกให้ครั้งเดียว)

### WHT ต่อบรรทัด + e-WHT + การนำส่ง (จาก PEAK UI)
- อัตราเลือกต่อบรรทัดเอกสาร: ไม่มี / 0.75 / 1 / 1.5 / 2 / 3 / 5 / 10 / 15 / กำหนดเอง → `document_line.wht_rate`; ยอด WHT รวมที่ document.wht_amount และตัดจากยอดชำระ
- แบบ (ภ.ง.ด.) เลือกจาก `contact.is_juristic` (53) / บุคคล (3; เงินเดือน = 1) / ต่างประเทศ `is_foreign` (54 + ภ.พ.36) — PEAK ใช้ contact.type; ของเราให้ override ต่อ payment ได้
- `wht_certificate.is_ewht` = หักผ่านธนาคาร (e-Withholding Tax) → ไม่ต้องออก 50 ทวิ กระดาษ และไม่รวมใน Text file
- `remit_status` pending → filed → paid ผ่าน `wht_remittance` (1 แบบ/เดือน) = คอลัมน์ "การนำส่ง" ใน PEAK; Text file รูปแบบ RD (ภ.ง.ด.1/3/53) สร้างจากใบรับรองที่ pending ของเดือนนั้น
- ฝั่งเราถูกหัก: `wht_received` เก็บหนังสือรับรองที่ได้รับจริง (received_certificate) เพื่อใช้เครดิต ภ.ง.ด.50 — ยอดใน 115403 ต้อง = Σ wht_received

## 5. ประกันสังคม

## 6. ภาษีเงินได้นิติบุคคล
- ภ.ง.ด.51 ครึ่งปี: ประมาณการกำไรทั้งปี ÷ 2 × อัตรา → 115404
- ภ.ง.ด.50 สิ้นปี: กำไรสุทธิทางภาษี × อัตรา (SME: 0% ≤ 300k, 15% 300k–3M, 20% > 3M; ทั่วไป 20%) → 590000 / 215301 หัก 115404 + 115403
- รายการบวกกลับทางภาษี (non-deductible): ค่ารับรองเกินเกณฑ์, ค่าปรับ, ภาษีซื้อต้องห้ามที่ไม่ใช่ต้นทุน, เงินบริจาคเกิน 2% — เก็บ flag `is_tax_deductible` ที่ account หรือ line

## 9. ปิดงวดและงบการเงิน

### ลำดับปิดเดือน
1. Register ใบกำกับภาษีซื้อที่ค้าง (115402 → 115401)
2. Reconcile ธนาคารทุกบัญชี
3. บันทึกค่าเสื่อมราคา, ค่าใช้จ่ายค้างจ่าย/จ่ายล่วงหน้า, ตัดจำหน่าย

## 9b. กฎเพิ่มเติม (ดู 08 §3)
- เอกสาร 1 ใบ **รับชำระได้หลายงวด** แต่ละงวดเป็น `payment_group` มี journal ของตัวเอง, WHT หักต่องวด (เป็น % ได้), void ได้ทีละงวด → เอกสารกลับเป็น WaitingPayment
- ภาษีซื้อ **หลายใบกำกับต่อ 1 expense** (1:N) ลงทะเบียนภายหลังได้
- **Statement** (รายการเดินบัญชีธนาคาร) แยกจาก payment → reconcile จับคู่ → `is_reconciled`
- **โอนระหว่างช่องทางเงิน** = journal Dr ปลายทาง / Cr ต้นทาง (+ WHT/เช็คได้)
- เอกสารฝั่งซื้อมีสถานะ "รอใบกำกับภาษี/ได้ใบกำกับแล้ว" แยกจากสถานะชำระ
- Journal มี Draft ได้ (default Approve)
- ReasonType ใบลดหนี้ใช้ตาราง 1-10 ตาม ม.82/10
