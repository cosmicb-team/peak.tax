# 12 — ขอบเขต Accounting & Tax Core (แยกเป็นอิสระ)

คำสั่ง (9 พ.ย. 2569): **Omnichannel ใช้บริการลูกค้าเท่านั้น ไม่เกี่ยวกับภาษี** โครงสร้างบัญชีและภาษีแยกเป็นระบบของตัวเอง
ผลคือ core นี้ไม่รู้จักแชท ช่องทาง หรือ AI ส่วนระบบอื่นไม่รู้จัก Dr/Cr หรือภาษี

## 1. อะไรอยู่ใน core / อะไรไม่อยู่

| อยู่ใน core (ของผม) | ไม่อยู่ใน core (ของคุณ) |
|---|---|
| ผังบัญชี 3 ชั้น, สมุดรายวัน, งบทดลอง, งบการเงิน DBD | แชท, inbox, ช่องทาง LINE/FB/WhatsApp |
| เอกสาร 25 ชนิด, เลขที่เอกสาร, ใบกำกับภาษี | AI ตอบแชท, knowledge, playbook |
| VAT ภ.พ.30/36, WHT ภ.ง.ด.1/2/3/53/54 + 50 ทวิ, CIT ภ.ง.ด.50/51, SSO | CRM, ติดตามลูกค้า, แคมเปญ |
| e-Tax Invoice/e-Receipt, รายงานภาษีซื้อ/ขาย | ตะกร้า/ออเดอร์ก่อนยืนยัน, ราคาโปรโมชัน |
| สินค้าคงเหลือ FIFO (มูลค่า), สินทรัพย์ + ค่าเสื่อม | สต๊อกหน้าร้าน/แสดงผลให้ลูกค้า |

| นโยบายบัญชี, ล็อกงวด, สิทธิ์ฝั่งบัญชี | ผู้ใช้/ทีมฝั่งบริการลูกค้า |

ไฟล์ของ core: `db/schema.sql`, `db/seed/*`, `api/openapi.yaml` (90 paths, ไม่มี Omni แล้ว), เอกสาร 00–11

## 2. จุดเชื่อมเดียว: API + Webhook ทั่วไป
ระบบใดก็ตาม (Omnichanel, POS, e-commerce, HR, Hermes) เป็นแค่ "ผู้เรียก" เหมือนกันหมด core ไม่มีโค้ดเฉพาะของระบบใด

| ทิศทาง | ช่องทาง | เนื้อหา |
|---|---|---|
| เข้า core | `POST /documents/{type}` (Draft) | เหตุการณ์ธุรกิจที่มีผลทางบัญชี: ขาย, รับเงิน, ซื้อ, จ่าย, คืนของ |
| เข้า core | `POST /contacts`, `GET /items` | ข้อมูลหลักที่ต้องใช้ออกเอกสาร |
| เข้า core | `POST /integrations/inbound/payment/{provider}` | เงินเข้าจริงจากธนาคาร/QR |
| ออกจาก core | webhook `document.*`, `payment.*`, `journal.posted`, `period.locked` | ผลลัพธ์ (เลขที่เอกสาร, สถานะ, ลิงก์ PDF) |
| ออกจาก core | `GET /public/documents/{token}` | หน้าใบเสร็จ/ใบกำกับให้ลูกค้าดู |

กฎที่ core บังคับกับทุกผู้เรียก:
1. ผู้เรียกส่งได้แค่ **ข้อเท็จจริงทางธุรกิจ** (ใคร ซื้ออะไร กี่บาท วันไหน จ่ายด้วยอะไร) ไม่ส่งบัญชีหรือยอดภาษี core คำนวณเอง
2. API key ของผู้เรียกภายนอก default scope = `view.*` + `create.<doc>` (Draft) เท่านั้น การอนุมัติ, void, ชำระเงิน, ล็อกงวด ทำในหน้าบัญชีของ core
3. `Idempotency-Key` บังคับทุก POST จากภายนอก (กันเอกสารซ้ำ)
4. ห้ามอ่านหรือเขียน schema `acct` ตรง
